name: portfolio-builder
description: 打开 GitHub 仓库勾选配置页，保存个人资料和项目展示配置，从所选仓库生成本地个人站点预览。用于创建或更新 GitHub 项目作品集。
---

使用当前聊天的实际工作目录作为 workspace。此 Skill 自带 Node.js 22+ 的配置服务和静态站点生成器，不需要安装 npm 依赖。

同一环境已有 `github-portfolio` 时，用户要求串联项目 README、Profile 和个人站点，应使用该手动工作台入口，复用保存的仓库与展示选择。本 Skill 下方流程保留为独立站点生成能力。

1. 检查 Node 和已登录的 GitHub CLI（gh）。本地服务通过 gh 读取仓库和 README，不使用聊天连接作为服务凭据。网络沙箱导致请求失败时，先在允许网络的执行上下文验证；不要据此判定登录失效。
2. 从 Skill 所在目录运行 `node scripts/server.mjs --workspace <当前工作目录绝对路径>`。服务绑定 127.0.0.1，输出配置页 URL。已有此工作目录的服务时复用；端口冲突时用 `--port <空闲端口>`。
3. 用 Codex 浏览器面板打开输出 URL，让用户勾选项目、设置个人资料、排序并编辑展示字段。页面保存到 workspace 的 `.portfolio-builder/config.json`；生成读取保存配置。
4. 用户点击“生成站点”后，服务读取所选 README 并生成 `.portfolio-builder/site/index.html`，页面显示进度和预览链接。工具只根据 README 和仓库资料整理内容，不宣称执行过项目或完成 AI 分析。没有保存选择时不擅自决定要公开的项目。
5. 验证保存后重载能恢复；生成站点的项目与勾选一致。GitHub 请求失败时保留已有生成结果，报告失败原因。

当前版本只生成本地预览，不提交、不推送、不发布，也没有后台定时调度。需要自动更新时复用已保存配置，另行接调度器。公开站点不暴露私有仓库链接；运行记录保留在本地。配置和生成目录不应提交 Git，凭据始终由 gh 管理。
